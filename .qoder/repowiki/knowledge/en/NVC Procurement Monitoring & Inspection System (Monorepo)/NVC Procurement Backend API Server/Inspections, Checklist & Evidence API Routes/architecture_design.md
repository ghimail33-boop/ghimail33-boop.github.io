Three sibling Express `Router` modules (`inspections.ts`, `checklists.ts`, `evidence.ts`) each export a default router mounted by the application server. All routes share a uniform shape: import `query` from `../db.ts` for parameterized PostgreSQL calls (using `$1..$N` placeholders), authenticate via `authenticate`/`requireRole` middleware from `../middleware/auth.ts`, and record mutations through `logAudit` from `../utils/audit.ts`. Business logic is thin — handlers parse `req.query`/`req.body`, build SQL strings inline, and return `res.json(rows)` or error objects; there is no service layer inside this scope. Cross-cutting concerns are centralized in shared modules rather than duplicated here. The inspection route additionally enforces role-based workflow transitions (only `admin`/`reviewer` can set status to `Verified`/`Closed`) and recomputes `completion_percentage` and `risk_score` after saving checklist results.
