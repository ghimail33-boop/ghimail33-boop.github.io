Three files form the auth + master-data surface of the server. `server/db.ts` is the single database abstraction: it lazily initializes either an external PostgreSQL connection pool (`pg.Pool`, driven by `DATABASE_URL`/`PG*` env vars) or an embedded persistent PGlite instance (`@electric-sql/pglite`) under `data/pgdata`. On first run it executes `database/schema.sql`, runs idempotent migrations from `database/migrations/*.sql` tracked in a `schema_migrations` table, then loads `database/seed.sql` to populate demo data; all SQL access goes through the exported `query(text, params)` helper so route handlers never touch `pg` or `pglite` directly. `server/routes/auth.ts` defines `/login`, `/me`, `/users` (CRUD) using bcrypt password hashing, JWT token generation via `../middleware/auth.ts`, role-based guards (`requireRole(['admin'])`), and audit logging via `../utils/audit.ts`. `server/routes/master.ts` exposes read-only endpoints for checklist stages, provinces, districts, municipalities, ministries, offices, fiscal years, and roles, with optional query filters built as parameterized SQL strings. Both routers export an Express `Router` default and depend only on shared middleware, utils, and the db layer — no cross-import between the two route files.
