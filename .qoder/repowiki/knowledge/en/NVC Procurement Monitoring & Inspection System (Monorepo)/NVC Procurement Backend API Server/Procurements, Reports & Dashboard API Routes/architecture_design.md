Three sibling Express `Router` modules (`procurements.ts`, `reports.ts`, `dashboard.ts`) each create a `Router()` instance and export it as the module default, intended to be mounted by a parent router. All routes delegate data access to a shared `../db.ts` `query()` helper that executes parameterized PostgreSQL statements; no ORM is used. Authentication is enforced via middleware: `authenticate` (from `../middleware/auth.ts`) plus optional `requireRole([...])` guards on mutating routes in `procurements.ts`. Audit logging is centralized through `../utils/audit.ts`'s `logAudit`, invoked after successful CREATE/UPDATE operations. The three files partition concerns cleanly: `procurements.ts` handles list/detail/create/update of procurement records and their document checklists; `reports.ts` aggregates an inspection's checklist items, findings, corrective actions, evidence, and stats into a single packet and provides CSV exports; `dashboard.ts` computes read-only KPIs, compliance/risk distributions, stage-level summaries, province breakdowns, and recent alerts. Dependency direction is one-way: routes → db/middleware/utils; there are no cross-imports between these three route files.
