The application is bootstrapped in `main.tsx` and mounted as `<App>` in `App.tsx`, which wraps the entire tree with `AuthProvider` (from `context/AuthContext`) and `ToastProvider` (from `components/Toast`). `MainApp` owns all cross-cutting state — current tab, badge counts, modal visibility, and navigation parameters — and renders a fixed layout of `Header` + `Sidebar` + a content `<main>` that conditionally mounts one of eight domain view components (`DashboardView`, `ProcurementsView`, `InspectionsView`, `FindingsView`, `CorrectiveActionsView`, `MasterChecklistView`, `ReportsView`, `AuditLogsView`). Cross-view coordination happens via props: navigation uses `handleNavigate(tab, filter)`, modals are lifted to `App` and opened by child views through callbacks (`onOpenNewModal`, `onOpenFindingWithPreload`, `onOpenEvidenceUpload`, `onOpenReportPrint`). All data access goes through a single `api` client in `services/api.ts`, which calls `/api/*` endpoints using a Bearer token read from `localStorage('nvc_token')`; every view consumes this client directly. Domain shapes are centrally declared in `types/index.ts` and imported by both the API client and every view/modal, forming the contract between frontend and backend.
